# Decisions and assumptions

> Kept up to date during the build. The full reasoning is in [docs/PLAN.md](docs/PLAN.md) §12–15.

## Stack decisions

| Decision                         | Why                                                                                                                                                     | Alternatives considered                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| NestJS (Node + TS) backend       | The brief allows only Node.js or Laravel. Nest's dependency injection makes swapping the product source and email provider a provider binding           | Fastify with hand-written layers (lighter, less structure); FastAPI was first proposed but is **not allowed** by the brief |
| **NestJS 11, not 12**            | Nest 12 is ESM-only, which adds friction with Jest, ts-jest and Prisma's CommonJS client for no PoC benefit. 11.x is still patched                      | Nest 12 + ESM Jest config                                                                                                  |
| **Prisma 6.19, not 7/8**         | Prisma 7 needs driver adapters plus a `prisma.config.ts` rewrite; 8 is an RC. 6.x is stable and well documented. The upgrade is listed under next steps | Prisma 7 with `@prisma/adapter-pg`                                                                                         |
| PostgreSQL + Prisma              | Featured picks and enquiries are business data that needs a durable home; Postgres maps to AWS RDS                                                      | A JSON file for picks (no persistence for leads); SQLite (not AWS-managed)                                                 |
| Shared `contracts` package (Zod) | One definition of the API shapes and validation rules for client and server                                                                             | OpenAPI codegen (more tooling than a PoC needs)                                                                            |
| Mailpit for email                | Free, local, and the reviewer can see the inbox                                                                                                         | Ethereal (needs network + account), console logging (can't show the inbox)                                                 |

## Design decisions (Phase 1)

| Decision                                                                                   | Why                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ports are abstract classes** (`ProductSource`, `FeaturedRepository`, `CacheStore`)       | They act as both the TypeScript interface and the Nest DI token, so no string tokens or `@Inject()` boilerplate are needed                                                                                                                                                                                                                         |
| **Search and filtering live in the `ProductSource` port**, not in a service                | Changed from the plan. A real catalogue (Postgres, OpenSearch, a PIM) should run search in its own engine. Putting queries on the port means a future adapter can do that instead of loading everything into memory                                                                                                                                |
| **`SnapshotProductSource` base class**                                                     | Fake Store has about 20 products, so the adapter loads the whole list, caches it (TTL, one shared refresh at a time) and answers every query from it. Large sources would implement the port directly                                                                                                                                              |
| **Stale-on-error**                                                                         | If Fake Store fails after the first load, the last good catalogue is served, with a retry every 30s, instead of an error page                                                                                                                                                                                                                      |
| **Fake Store single-product endpoint not used**                                            | `GET /products/{unknown}` returns **200 with an empty body**, not a 404 (found by probing the live API). Looking products up in the loaded list gives correct 404s                                                                                                                                                                                 |
| **Product ids are strings**                                                                | The contract doesn't depend on Fake Store's numeric ids                                                                                                                                                                                                                                                                                            |
| **Our own `Product` shape**                                                                | The adapter maps Fake Store → contract (price → `{ amount, currency }`, `image` → `imageUrl`, category → `{ slug, name }`). The client never sees the upstream shape                                                                                                                                                                               |
| **Bad upstream items are skipped**                                                         | One malformed record is logged and dropped instead of failing the whole catalogue                                                                                                                                                                                                                                                                  |
| **`FixtureProductSource`** (`PRODUCT_SOURCE=fixture`)                                      | Offline data for tests and demos. Its ids match Fake Store, so seeded picks still resolve, and it shows a source swap as a config change                                                                                                                                                                                                           |
| **Featured picks in a file**                                                               | `featured-picks.ts` (seeded to the DB with Postgres) stands in for an admin screen                                                                                                                                                                                                                                                                 |
| **HTTP client uses native `fetch`** with timeout and 1 retry (5xx and network errors only) | No extra dependency. Tests stub `fetch` instead of using nock                                                                                                                                                                                                                                                                                      |
| **Health at `/health`** (outside `/api/v1`), 503 when the DB is down                       | For Docker and AWS load-balancer health checks                                                                                                                                                                                                                                                                                                     |
| **`multer` override → 2.5.0**                                                              | Nest 11.2.8 (the latest 11.x) pins multer 2.4.0, which has a high-severity DoS advisory. A minor override fixes it. multer is only used by Nest's file-upload interceptors, which we don't use. (`npm ls` shows it as "invalid" because of the exact pin; that's expected with overrides)                                                          |
| **Accepted risk: `deepmerge-ts` < 8 under the Prisma 6 CLI**                               | High advisory (stack exhaustion on recursive objects), fixed only in 8.0.0. It's used only by the Prisma **CLI** to merge its own config files (generate/migrate). It never sees request data and isn't loaded by the running API. Forcing a major version under Prisma 6 could break the CLI. It goes away with the Prisma 7 upgrade (next steps) |
| **Accepted risk: Vitest 3 / tinypool advisories (dev only)**                               | Critical advisories in the test runner (prototype pollution in worker options; path traversal via mock redirects), fixed only in Vitest 5. They're only reachable by running malicious test code on a developer machine, and nothing ships to users. Switching test runner majors mid-build wasn't worth the risk; listed under next steps         |

## Design decisions (Phase 2)

| Decision                                                                                     | Why                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Pages keep working when the DB is down**                                                   | Picks are nice-to-have; product data is essential. If loading picks fails, or takes more than **1.5s**, home and category pages fall back to best rated and the error is logged. The timeout was added after a live test showed each DB-down request waited about 5.5s for Prisma's connection timeout |
| **Save first, then email**                                                                   | The enquiry is a lead. It's written to Postgres before the email is attempted, so an email outage never loses one                                                                                                                                                                                      |
| **Email failure still returns `201`**                                                        | The customer's part is done and their enquiry is safe. The failure is stored as `EMAIL_FAILED` with the reason, so sales can follow up and a retry job can pick it up later. If the enquiry **can't be saved**, the customer gets an error so they know to try again                                   |
| **Email sent during the request**, not queued                                                | Simplest thing that meets the acceptance criterion. SMTP timeouts are capped (10–15s). Next step: transactional outbox + worker (SQS) so the request never waits on email                                                                                                                              |
| **`Mailer` port with SMTP + log adapters**                                                   | SMTP covers Mailpit locally and most production providers, including AWS SES's SMTP interface, so moving to SES is configuration only. `MAILER=log` lets a developer run without an SMTP server                                                                                                        |
| **`Reply-To` is the customer**                                                               | Sales can reply directly from the inbox                                                                                                                                                                                                                                                                |
| **Customer input is escaped in the HTML email**; the subject is flattened to one line        | Stops markup injection into the sales inbox and header injection. Covered by tests                                                                                                                                                                                                                     |
| **Product title is saved with the enquiry**                                                  | The product source may change or drop the product later; the lead must still make sense                                                                                                                                                                                                                |
| **Honeypot field (`website`)**                                                               | Cheap bot filter. A filled honeypot gets a normal-looking `201`, so bots learn nothing, but nothing is stored or sent                                                                                                                                                                                  |
| **Rate limit: 5 enquiries per minute per IP** (`ENQUIRY_RATE_LIMIT_PER_MIN`), enquiries only | Limits spam and abuse of the email channel without affecting browsing. In-memory store; a Redis store is needed once there are several API instances                                                                                                                                                   |
| **Real SMTP tested in-process** (`smtp-server` dev dependency)                               | Docker wasn't available while building, so the SMTP adapter is tested against a real SMTP server inside the test process, the same protocol path as Mailpit                                                                                                                                            |

## Design decisions (Phase 3: web)

| Decision                                                                              | Why                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **React 19 + Ant Design 6 + MobX 6 + React Router 7 + Vite 7**                        | Newest stable lines with known-good compatibility: AntD 6 supports React 19 natively (no compatibility shim), and mobx-react-lite 4.1 declares React 19 support. Newer majors (MobX 7, React Router 8, Vite 8) were skipped for a time-boxed PoC |
| **Layers: `HttpClient → services → stores → hooks → pages → components`**             | Each layer only knows the one below. ESLint blocks `axios` and `src/api/**` imports in components, pages and hooks, so the API layer can't leak into UI code                                                                                     |
| **Every API response is checked against the shared Zod schema** in `HttpClient`       | Catches contract drift at the boundary (`INVALID_RESPONSE`) instead of as a broken page later. Every failure becomes one `ApiError` type with a friendly message                                                                                 |
| **Services injected into stores** (`RootStore(services)`)                             | Stores are testable with fakes, and a new backend only changes the service layer                                                                                                                                                                 |
| **`AsyncResource<T>`**: one loading/error/data helper reused by every store           | Loading and error handling is written once. "Latest wins": a slow, out-of-date response can't overwrite a newer one (e.g. fast typing in search)                                                                                                 |
| **Hooks return plain snapshots, not live MobX objects**                               | Presentational components (e.g. `PageState`) stay MobX-free and still update. See AI_USAGE.md for the bug that led to this rule                                                                                                                  |
| **Search term lives in the URL** (`/search?q=`)                                       | Results survive refresh, back/forward and sharing. The search runs on the Search button or Enter, as the acceptance criteria describe                                                                                                            |
| **`PageState`**: one component for loading / error + retry / not found / empty        | Every page handles failure the same way, and none can forget to                                                                                                                                                                                  |
| **Theme: tokens → AntD `ConfigProvider` (`cssVar`) → CSS Modules via `var(--ant-…)`** | One file (`theme/tokens.ts`) holds brand colours, fonts and radius. Dark mode is AntD's dark algorithm plus a couple of overrides. No inline styles anywhere (ESLint), and no literal colours in CSS (stylelint: hex, named, rgb/hsl blocked)    |
| **Layout sizing lives in CSS, not `tokens.ts`**                                       | CSS variables can't be set from TS without inline styles; one source of truth beats two                                                                                                                                                          |
| **CSS Modules only on our own elements**; AntD styled via tokens and props            | Overriding AntD's internal classes fights its CSS-in-JS specificity and breaks on upgrades                                                                                                                                                       |
| **Theme choice remembered; defaults to the OS preference**                            | Storage access is wrapped, so blocked storage (private mode) doesn't break the app                                                                                                                                                               |
| **Product photos always on a white panel**, even in dark mode                         | Fake Store images have baked-in white backgrounds; a white panel looks deliberate instead of broken                                                                                                                                              |
| **Compact rating on tiles** (★ 4.7 (500)), full stars on the product page             | Full star rows wrapped badly in narrow cards (seen in screenshots, not tests)                                                                                                                                                                    |
| **Vendor chunks** (react / antd / state)                                              | App code is ~18 kB and changes most often; vendors stay cached across releases                                                                                                                                                                   |
| **Tests: whole app rendered with real stores + MSW at the HTTP boundary**             | Acceptance tests mirror the brief's criteria one-to-one and exercise every layer except the network                                                                                                                                              |

## Design decisions (Phase 4: enquiry UI)

| Decision                                                                                  | Why                                                                                                                                                                                         |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Enquiry form in a modal** on the product page                                           | The customer stays in context; the AC's "subsequent form" doesn't need its own URL. The dialog swaps to "Thank you" in place                                                                |
| **Form validated with the API's own Zod schema** (`zodRule(CreateEnquirySchema.shape.x)`) | One definition of valid, so the form and API messages match exactly. The API still validates (never trust the client)                                                                       |
| **`noValidate` on the form**                                                              | The browser's own `type="email"` validation blocked submit and showed a native tooltip, hiding our messages for the other fields. Found while debugging a test; confirmed in a real browser |
| **Required rules marked explicitly** (`{ required: true }`)                               | AntD skips custom validators for never-touched fields unless the rule is required, so an untouched Name would have passed client-side                                                       |
| **Validate on blur, not on every keystroke**                                              | Less noise while typing; everything is still validated on submit                                                                                                                            |
| **API errors shown in the form**: alert + field errors from a 400; typed values kept      | A rate limit (429) or server-side rejection is explained, and the customer doesn't have to retype                                                                                           |
| **Message pre-filled** ("I'm interested in {product}.")                                   | Faster to complete, and sales sees the product even if the customer writes nothing else                                                                                                     |
| **Thank-you names the person, product and email**                                         | Confirms what was sent and where the reply will go                                                                                                                                          |
| **Reset on open, not on close**                                                           | Avoids the form flashing back during the dialog's close animation                                                                                                                           |
| **Thank-you button says "Done"**, not "Close"                                             | The dialog's ✕ is already labelled "Close"; two identical names are ambiguous for screen-reader users                                                                                       |
| **Visual check via the DevTools Protocol** (scratchpad script, not committed)             | Drove headless Edge through open → validation → submit → thank-you in light and dark, with the POST answered by the browser because there was no DB locally                                 |

## Design decisions (Phase 5: containers)

| Decision                                                                    | Why                                                                                                                                                                                                                               |
| --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **One root `Dockerfile` with targets** (`api`, `migrate`, `web`)            | Changed from the plan's "Dockerfiles for api and web". It's a monorepo with one lockfile, so the images share a single `npm ci` layer instead of installing twice, which matters for the reviewer's 10-minute budget              |
| **API image has production dependencies only**                              | A separate `npm ci --omit=dev` for just the API and contracts workspaces (no React, Vite or Jest). The Prisma client is generated in the build stage and copied in. Runs as the non-root `node` user                              |
| **Migrations + seed run as a one-shot `migrate` service**, not on API start | Several API replicas would race each other on migrations. A separate job maps to a pipeline step or an ECS task on AWS. The API waits for it with `service_completed_successfully`                                                |
| **nginx serves the web build and proxies `/api` on the same origin**        | No CORS, and the browser never learns the API's address. Same shape as CloudFront + S3 with an `/api/*` behaviour. Hashed assets are cached for a year; `index.html` is never cached, so releases show up at once                 |
| **API port not published to the host** in Docker                            | Everything goes through nginx at http://localhost:8080, as in production. It also avoids clashing with something already on port 3000 on the reviewer's machine                                                                   |
| **`TRUST_PROXY_HOPS`** (default 0; 1 in Docker)                             | Behind nginx, every customer would share nginx's IP and therefore one rate limit. Express now reads the client IP from `X-Forwarded-For`, trusting exactly as many hops as there are proxies, so it can't be spoofed further back |
| **Compose works without a `.env` file**                                     | Every value has a default, so `docker compose up --build` is the only step. A `.env` overrides them                                                                                                                               |
| **Alpine base images**                                                      | Small downloads. Prisma's engine needs OpenSSL, installed explicitly; the client is generated inside the same base image, so the right engine is picked automatically                                                             |
| **Playwright dropped** (first item in the plan's cut order)                 | Time-box. The same flow was checked in a real browser with a DevTools-protocol script during Phase 4, and the acceptance criteria are covered by page tests                                                                       |

## Change after Phase 5: the database is optional

Requested by the owner. The brief doesn't ask for a database, and the reviewer, like the build laptop, may not have Docker.

| Decision                                                                                          | Why                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`STORAGE=memory\|postgres`, default `memory`**                                                  | `npm install`, `npm run build` and the two dev servers are all it takes: no database, migrations or seed. Docker keeps `postgres`                                                                                                                                                                                            |
| **An in-memory adapter for each repository port**, chosen by a factory                            | The same swap-by-configuration pattern as the product source and mailer; no service changed. The in-memory classes were the test fakes, promoted to adapters                                                                                                                                                                 |
| **Picks live in one file, `featured-picks.ts`**                                                   | Memory mode reads it directly; the Postgres seed imports it. One list, so the two modes can't drift                                                                                                                                                                                                                          |
| **In-memory enquiries capped at the newest 1000**                                                 | The endpoint is public, so memory must stay bounded. Older ones were already emailed                                                                                                                                                                                                                                         |
| **Health reports `storage`, and `db: "disabled"` in memory mode (still 200)**                     | Nothing is down, so a load balancer mustn't mark the API unhealthy                                                                                                                                                                                                                                                           |
| **`DATABASE_URL` required only for `postgres`**                                                   | Checked at startup with a clear message                                                                                                                                                                                                                                                                                      |
| **Accepted trade-off**                                                                            | Memory mode loses stored enquiries (including `EMAIL_FAILED` ones) on restart and isn't shared between instances. Fine for the PoC; Postgres is the production path                                                                                                                                                          |
| **Web dev proxy follows `API_PORT` from `.env`**                                                  | One setting moves both when port 3000 is taken                                                                                                                                                                                                                                                                               |
| **Built-in dev inbox** (`apps/api/dev/dev-inbox.mjs`) instead of requiring Mailpit outside Docker | Without Docker there was nowhere to see the sales email, so the Enquiry criterion couldn't be shown. Real SMTP into a 150-line local inbox on Mailpit's ports needs no download or account. The API is unchanged; the same SMTP adapter is used either way. Dev-only: binds to 127.0.0.1 and isn't in the API build or image |
| **`npm run dev`: one command for inbox + API + web**                                              | The brief asks for one or two setup commands. Without Docker it's now `npm install` then `npm run dev`; a small Node script, no extra dependency                                                                                                                                                                             |

## Assumptions

1. **"Top rated" products are chosen by the entrepreneur** in [featured-picks.ts](apps/api/src/modules/catalog/featured-picks.ts), and seeded into the DB when `STORAGE=postgres`. The Fake Store rating is used only as a fallback.
2. **Home page:** chosen products in the chosen order. Picks the source no longer has are skipped and logged. If fewer than 5 remain, the best rated fill the gap so the home page is never empty.
3. **Category "top rated":** that category's chosen products. With none chosen, the 3 best rated (average, then review count). "Additional products" means the rest of the category, alphabetical, with no repeats.
4. **Search:** case-insensitive substring match on title, description and category name, with title matches listed first. Blank or over-100-character terms are rejected (400). Every result really does contain the term.
5. **Prices are AUD.** Fake Store has no currency.
6. **Category names** are title-cased for display (`men's clothing` → `Men's Clothing`). The source's spelling ("Jewelery") is kept.
7. **Enquiry form fields:** name, email and message are required; phone is optional. One enquiry is about one product, and the product is attached automatically.
8. **"The sales inbox"** is one configured address (`SALES_INBOX_EMAIL`). Locally, that's Mailpit.
9. **No confirmation email to the customer.** The acceptance criteria only ask for the on-screen "Thank you". Sending email to an address typed into a public form also needs abuse safeguards first.
10. **Web only, responsive.** The brief allows web or mobile; a responsive web app covers phones without a native build.
11. **Data is fetched once per visit** (featured, categories, each category page and product). The API caches Fake Store for 5 minutes anyway; a long-open tab showing slightly old data is acceptable for a PoC.
12. **App name "Catalogue" and a blue primary colour are placeholders** until the creative work lands; both are one-line changes (`config/app.ts`, `theme/tokens.ts`).

## How the design supports growth

- **The three things the brief says will change are each one swap:**
  - **Product source:** a new `ProductSource` adapter plus one `case` in a factory. Search and filtering are on the port, so a real catalogue can run them in its own engine.
  - **Email provider:** AWS SES works through SMTP with configuration only; an API-based provider is one `Mailer` adapter.
  - **Look and feel:** brand colours, fonts and radius live in `theme/tokens.ts`. No component has a literal colour or inline style, and lint enforces that.
- **AWS mapping:**

  | Piece           | Locally            | On AWS                                               |
  | --------------- | ------------------ | ---------------------------------------------------- |
  | Web             | nginx              | S3 + CloudFront                                      |
  | API             | `api` container    | ECS Fargate behind an ALB; stateless, scales out     |
  | Database        | memory or Postgres | RDS                                                  |
  | Email           | Mailpit            | SES                                                  |
  | Migrations      | `migrate` job      | pipeline step or one-off ECS task                    |
  | Secrets         | `.env`             | SSM Parameter Store / Secrets Manager                |
  | Cache and limit | in memory          | ElastiCache Redis (before running a second instance) |
  | Health          | `/health`          | ALB target-group health check                        |

- **Contract first:** the Zod schemas in `packages/contracts` can generate OpenAPI docs and typed clients for a future mobile app.
- **Mobile:** the API is client-agnostic; the web app is already responsive.

## Next steps with another day

1. Admin screen and API for featured picks and the enquiry list, behind auth (Cognito).
2. Transactional outbox + retry worker (SQS) for enquiry emails; re-sends `EMAIL_FAILED`. Customer confirmation email once abuse safeguards exist.
3. CI (GitHub Actions): lint, typecheck, tests, Docker build, and a Playwright run (open → enquire → thank you, checked in Mailpit).
4. Redis-backed rate-limit store and cache before running more than one API instance.
5. Upgrades: Prisma 7 (driver adapters), NestJS 12 (ESM), Vitest 3 → 5 (clears its dev-only advisories).
6. Speed up the web test suite (a few minutes on a slow machine): e.g. turn off AntD style injection in jsdom, or move the full-flow tests to Playwright.
7. Route-level code splitting (`React.lazy`); Ant Design is ~240 kB gzipped of the first load.
8. Accessibility audit with axe and a manual screen-reader pass; SEO meta tags; image lazy-loading.
9. Cache expiry for client data (refetch on focus, or after N minutes).
10. Generated OpenAPI docs, and contract tests for the Fake Store adapter against the live API.
